Barista Caótico: cómo funciona por dentro

Machete para grabar el video y defender el código. Cada sección explica qué hace una parte del juego, qué script la maneja y qué tema de la materia usa.

El juego en 1 minuto

Es una cafetería vista desde arriba. Manejás al barista con las flechas o WASD y preparás bebidas para los clientes que llegan al mostrador. Cada cliente tiene su bandeja: ahí se arma el pedido (bebida y, a veces, galletita) y se entrega.

TeclaQué hace
Flechas / WASDMover al barista
Z · X · CAgarrar de las despensas: café en grano, leche o chocolate; o una de las tres galletitas
EUsar la estación más cercana (máquinas, repisas, bandejas, tacho)
RSacar un producto de la bandeja (si te equivocaste)
EscPausa

Recetas

CaféGranos → moledora → café molido → cafetera → café
Leche espumadaLeche → cafetera
ChocolateChocolate → chocolatera
Con lecheCafé o chocolate + leche espumada, juntos en una repisa

Cómo se gana y cómo se pierde

  • Tutorial: 3 pedidos fijos (café, café con leche, chocolate), un cliente distinto cada vez, sin paciencia y con una guía paso a paso arriba.
  • Partida normal: vuelven dos clientes con pedidos al azar y con paciencia. A los 12 pedidos se abre un tercer puesto.
  • Ganás al entregar 15 pedidos. Perdés si se te van 3 clientes enojados.
  • Al terminar, el juego se congela con Time.timeScale = 0 y aparece un cartel con el resumen.

Estos números se cambian en el Inspector del GameManager (ordersToWin, ordersForThirdCustomer, maxLostCustomers), sin tocar código.

El inventario: qué tiene el barista en la mano

Script: PlayerInventory, en el objeto Player.

El enum ItemType: el idioma común del juego

Todos los objetos del juego están en una sola lista con nombre, un enum:

public enum ItemType
{
    None, CoffeeBeans, Milk, Chocolate,
    GroundCoffee, Coffee, FoamedMilk, HotChocolate,
    CoffeeWithMilk, ChocolateWithMilk,
    RedVelvetCookie, VanillaChocolateCookie, ChocolateCookie
}

Así es como el código diferencia cada cosa. La mano del barista, las máquinas, las repisas, las bandejas y los pedidos guardan un ItemType. Comparar es tan simple como item == PlayerInventory.ItemType.Milk.

Para decir en la defensa

Un enum es una lista de opciones con nombre. Por dentro Unity las guarda como números (None = 0, CoffeeBeans = 1…). Lo usé en lugar de strings porque si escribo mal un nombre el código no compila, mientras que con un string el error pasaría sin que me dé cuenta. Por eso los valores nuevos se agregan siempre al final: si cambio el orden, lo guardado en la escena cambia de significado.

Una sola variable y dos funciones

[SerializeField] private ItemType currentItem = ItemType.None;

public bool PickUpItem(ItemType newItem)
{
    if (HasItem())          // ya tiene algo: no puede agarrar otra cosa
    {
        hud.ShowMessage("Ya tenés algo en la mano...");
        return false;
    }
    currentItem = newItem;
    UpdateBubble();          // el globito arriba del barista muestra el objeto
    return true;
}

public void DropItem()
{
    currentItem = ItemType.None;
    UpdateBubble();
}
  • El barista lleva un solo objeto. None significa manos vacías.
  • currentItem es private: otros scripts lo leen con GetCurrentItem() y lo cambian solamente con PickUpItem o DropItem. Así nadie lo pisa por error.
  • PickUpItem devuelve bool: las máquinas lo usan para vaciarse solo si el barista pudo agarrar el producto.
  • [SerializeField] permite ver lo que tiene en la mano en el Inspector mientras jugás.

Agarrar ingredientes y galletitas

Scripts: IngredientStation y CookieStation (son iguales, cambian los objetos que entregan).

  1. En cada Update la despensa mide la distancia al barista con Vector2.Distance. Si está a menos de interactionDistance, se pinta de amarillo (resaltado).
  2. Lee las teclas con Input.GetKeyDown, y cada tecla corresponde a un ingrediente: 
    if (Input.GetKeyDown(KeyCode.Z))      GiveIngredient(ItemType.CoffeeBeans);
else if (Input.GetKeyDown(KeyCode.X)) GiveIngredient(ItemType.Milk);
else if (Input.GetKeyDown(KeyCode.C)) GiveIngredient(ItemType.Chocolate);
  3. GiveIngredient vuelve a chequear la distancia y llama a inventory.PickUpItem(...). Si el barista ya tiene algo, el inventario lo rechaza y muestra el aviso.

Galletitas: Z red velvet, X vainilla con chocolate, C chocolate.

¿Por qué no usan la E?

Las despensas tienen tres cosas, así que cada una necesita su tecla. Por eso no heredan de InteractiveStation: no tienen un único Interact. Además, si el juego está en pausa (Time.timeScale == 0), no hacen nada.

Cómo funciona la E: herencia y la estación más cercana

Scripts: InteractiveStation (clase base) y PlayerInteraction (en el Player).

La herencia

Moledora, cafetera, chocolatera, repisa, bandeja y tacho heredan de InteractiveStation:

public class InteractiveStation : MonoBehaviour
{
    public virtual void Interact(PlayerInventory inventory) { ... }
    protected void Notify(string message, bool isError = true) { ... }
}

public class CoffeeMachine : InteractiveStation
{
    public override void Interact(PlayerInventory inventory) { /* lo suyo */ }
}
  • virtual en la base significa "cada estación puede reemplazar esta función". Cada estación la reemplaza con override.
  • Gracias a eso, el barista no necesita saber qué estación tiene adelante: llama a station.Interact(inventory) y cada una reacciona a su manera.
  • protected Notify(...) se escribe una sola vez en la base y la usan todas las hijas. Muestra el mensaje en el HUD y hace sonar el error. isError es un parámetro opcional: el tacho pasa false porque tirar algo no es un error.
Para decir en la defensa

Es la misma idea que MonoBehaviour: todos mis scripts heredan de MonoBehaviour y por eso tienen Start y Update. Mis estaciones heredan de InteractiveStation y por eso todas tienen Interact.

Encontrar la estación más cercana

  1. En Start, una sola vez, FindObjectsByType<InteractiveStation> junta todas las estaciones en un array (incluidas las desactivadas, como las bandejas de clientes que todavía no llegaron). Buscar es lento, por eso no se hace en cada frame.
  2. Se arman arrays paralelos: en la posición i de drawings[] está el SpriteRenderer de la estación i, y en colliders[], su collider.
  3. FindNearestIndex recorre el array con un for, como un "buscar el mínimo": 
    float shortestDistance = reach;              // 0.8: más lejos no cuenta
for (int i = 0; i < stations.Length; i++)
{
    if (!stations[i].gameObject.activeInHierarchy) continue;   // ocultas: no

    Vector2 point = stations[i].transform.position;
    if (colliders[i] != null)
        point = colliders[i].ClosestPoint(transform.position);   // borde más cercano

    float distance = Vector2.Distance(transform.position, point);
    if (colliders[i] == null) distance = distance - radiusWithoutCollider;

    if (distance < shortestDistance) { shortestDistance = distance; nearestIndex = i; }
}
  4. Se mide hasta el borde del collider con ClosestPoint (no lo vimos en clase: devuelve el punto del collider más cercano al barista). Las máquinas son grandes y medir al centro hacía que se activaran desde muy lejos. Las bandejas no tienen collider, así que se mide a su centro y se le resta un radio.
  5. La estación elegida se resalta (se tiñe de amarillo) para que sepas qué vas a usar antes de apretar E.
  6. Con R se usa la misma búsqueda pero solo entre bandejas (GetComponent<Tray>() == null → continue).

Las máquinas: cómo diferencia cada una y cómo reacciona

Las tres heredan de InteractiveStation y funcionan con la misma idea: un temporizador en Update con Time.deltaTime. Lo que cambia es qué aceptan y qué devuelven. Cada máquina tiene su propio Interact, y ahí está la diferencia.

MáquinaAceptaDevuelveTiempoCómo decide
MoledoraCafeGroundCoffee3 sif
CafeteraGroundCoffee o LecheCoffee o FoamedMilk4 s / 3 sswitch
ChocolateraChocolateHotChocolate4 sif

Lo que pasa al apretar E (en este orden)

  1. ¿Está trabajando? (preparing == true) → avisa "está trabajando" y no hace nada más.
  2. ¿Tiene algo listo? → intenta dárselo al barista con PickUpItem. Si tiene las manos ocupadas, no se vacía.
  3. ¿Está vacía? → mira qué trae el barista:
    • Si es lo que la máquina acepta: DropItem(), se pone preparing = true y timeRemaining = preparationTime.
    • Si no: Notify("La moledora necesita granos de café.").

La cafetera usa switch

switch (inventory.GetCurrentItem())
{
    case PlayerInventory.ItemType.GroundCoffee:
        inventory.DropItem();
        StartPreparing(ItemType.GroundCoffee, ItemType.Coffee, coffeeTime);
        break;
    case PlayerInventory.ItemType.Milk:
        inventory.DropItem();
        StartPreparing(ItemType.Milk, ItemType.FoamedMilk, milkTime);
        break;
    default:
        Notify("La cafetera necesita café molido o leche.");
        break;
}

Como acepta dos cosas distintas, guarda qué está preparando en productInProgress y, al terminar, lo pasa a readyProduct.

El temporizador

private void Update()
{
    if (!preparing) return;              // no está trabajando: nada que contar

    timeRemaining -= Time.deltaTime;     // le resto lo que duró este frame

    if (timeRemaining <= 0f)
    {
        preparing = false;
        coffeeReady = true;
        ShowInBubble(ItemType.GroundCoffee, true);
        soundEffects.MachineReady();
    }
}
Para decir en la defensa

Time.deltaTime es lo que tardó el último frame. Si lo voy restando, la máquina tarda los mismos segundos en una compu rápida que en una lenta. No usé corrutinas porque no las vimos. Además, como en la pausa timeScale es 0, deltaTime vale 0 y el temporizador se frena solo.

El globo de la máquina: mientras trabaja muestra el ingrediente medio transparente (Show(item, false), donde ready es un parámetro opcional). Cuando termina muestra el resultado bien visible.

La repisa: apoyar y combinar

Script: Shelf. Tiene 2 espacios y trabaja con arrays:

  • slotPositions[] (Vector3, se edita en el Inspector): dónde se dibuja cada espacio. La cantidad de elementos define cuántos espacios hay.
  • slots[] (ItemType): qué hay en cada espacio. Un array nuevo arranca lleno de None (el 0 del enum), o sea, vacío.
  • bubbles[]: el dibujo de cada espacio. Es otro array paralelo.

Al apretar E

  1. Si llevás algo, primero intenta combinar. Recorre los espacios con un for y llama a Combine(slots[i], itemInHand): 
    if (IsPair(a, b, ItemType.Coffee, ItemType.FoamedMilk))
    return ItemType.CoffeeWithMilk;
if (IsPair(a, b, ItemType.HotChocolate, ItemType.FoamedMilk))
    return ItemType.ChocolateWithMilk;
return ItemType.None;   // no combinan
    IsPair acepta los dos en cualquier orden: (a == x && b == y) || (a == y && b == x).
  2. Si no combina, lo apoya en el primer espacio libre (FindFreeSlot devuelve el índice, o -1 si está llena).
  3. Con las manos vacías agarra lo del espacio ocupado más cercano al barista.

Las bandejas

Script: Tray. Cada cliente tiene la suya (se asigna en el Inspector con customerTray). Guarda dos cosas: drink y cookie, ambas ItemType.

Al apretar E, según lo que lleves

Llevás…Qué pasa
NadaEntrega: le pregunta al cliente IsCorrectOrder(drink, cookie). Si es correcto, vacía la bandeja y llama a customer.ReceiveOrder(); si no, avisa "no es lo que pidió".
Una bebida listaLa apoya, si no había otra bebida.
Una galletitaLa apoya, si no había otra galletita.
Un ingrediente sin preparar"Eso no se puede servir: primero hay que prepararlo."

IsDrink y IsCookie son funciones que devuelven bool usando || (alcanza con que una opción coincida).

R saca primero la galletita y después la bebida, por si te equivocaste.

Lo apoyado se ve sobre la bandeja: en Start se crean dos dibujos con el catálogo (uno para la bebida, otro para la galletita), y UpdateDrawings() se llama cada vez que algo cambia. Si el objeto es None, el dibujo se oculta solo.

La bandeja empieza desactivada y la activa el cliente cuando llega al mostrador.

Los clientes

Scripts: Customer (el pedido y la paciencia) y CustomerMovement (caminar). Hay tres clientes en la escena, cada uno con su puesto y su bandeja.

Caminar (CustomerMovement)

Dos Transform asignados en el Inspector: entryPoint (la puerta) y waitPoint (su puesto). En Update, si está entering, avanza con Vector3.MoveTowards(..., speed * Time.deltaTime). Cuando la distancia es casi 0, avisa customer.ShowOrder(). Para salir hace lo mismo al revés y, al llegar, llama a customer.FinishedLeaving().

El pedido

El GameManager le asigna bebida y galletita con AssignOrder. El pedido se ve en un globo arriba del cliente (OrderBubble). Para chequearlo:

public bool IsCorrectOrder(ItemType drink, ItemType cookie)
{
    return drink == orderedDrink && cookie == orderedCookie;
}

Si el pedido no lleva galletita, orderedCookie es None, y la bandeja también tiene que tener None.

La paciencia

  • La paciencia depende del pedido: maxPatience + extraWithMilk (10 s si es "con leche") + extraCookie (6 s si lleva galletita). Los pedidos más largos tienen más tiempo.
  • En Update: currentPatience -= Time.deltaTime, y la barra (Slider) toma el valor currentPatience / orderPatience (de 1 a 0).
  • PaintBar usa if / else if / else: verde si queda más de la mitad, amarilla si queda más de un cuarto y roja si queda menos.
  • Cuando llega a 0, avisa a gameManager.CustomerOutOfPatience(this).
  • En el tutorial no hay paciencia: ShowOrder solo la arranca si gameManager.IsTutorialFinished().

La pausa entre clientes

Después de salir no entra otro enseguida: FinishedLeaving pone paused = true y un temporizador de 2 s (pauseBetweenCustomers). Cuando termina, le avisa al GameManager.

GameManager: las reglas

Es el "árbitro": cuenta pedidos y clientes perdidos, decide qué pide cada cliente y cuándo se gana o se pierde.

El tutorial con switch

switch (completedOrders)
{
    case 0: customer = customer1; drink = ItemType.Coffee;      break;
    case 1: customer = customer2; drink = ItemType.CoffeeWithMilk;       break;
    case 2: customer = customer3; drink = ItemType.HotChocolate; break;
}

Cuando se completan los 3 (const int TutorialOrders = 3), FinishTutorial() pone tutorialFinished = true y hace entrar a los clientes 1 y 2 con pedidos al azar.

Pedidos al azar con arrays

private ItemType[] drinks = { Coffee, CoffeeWithMilk, HotChocolate, ChocolateWithMilk };
private ItemType[] cookies = { None, RedVelvetCookie, VanillaChocolateCookie, ChocolateCookie };

int drinkIndex = Random.Range(0, drinks.Length);
int cookieIndex = Random.Range(0, cookies.Length);
customer.AssignOrder(drinks[drinkIndex], cookies[cookieIndex]);

Como None está en el array de galletitas, hay 1 chance en 4 de que el pedido no lleve galletita. La primera vez que alguien pide galletita aparece una pista en el HUD (cookiesExplained).

Contadores, propinas y el tercer puesto

  • OrderCompleted: completedOrders++, suma la propina, actualiza el HUD y suena "entregar".
  • Propina = baseTip + maxExtraTip × paciencia que le quedaba (de 0 a 1). Con 5 y 10, un cliente atendido rápido deja hasta $15, y uno a punto de irse, $5. En el tutorial siempre $5. 
    return baseTip + (int)(maxExtraTip * customer.GetPatiencePercent());
    El (int) convierte el resultado a entero (corta los decimales).
  • CustomerLeft: entra un cliente nuevo y, si se llegó a ordersForThirdCustomer, se activa el tercero (una sola vez, con el bool thirdCustomerActive).
  • CustomerOutOfPatience: lostCustomers++; si llega a 3, LoseGame(); si no, el cliente se va enojado.

Ganar, perder, reiniciar

  • EndGame() frena la paciencia de los tres clientes (un for sobre el array customers) y pone Time.timeScale = 0: todo lo que usa deltaTime se congela.
  • Se activa victoryPanel o defeatPanel con un resumen armado concatenando strings. En la victoria, el comentario cambia según cuántos clientes perdiste (if / else if / else).
  • Los botones llaman a RestartGame() (vuelve a cargar la escena con SceneManager.LoadScene) o a GoToMenu(). Antes de cargar, ponen timeScale en 1 otra vez.

La guía del tutorial

Script: TutorialGuide (en el HUD). Muestra arriba "Tu cliente quiere…" más una sola instrucción, y una flecha que rebota sobre la estación a la que tenés que ir.

  • El GameManager le avisa StartOrder(...), OrderDelivered() y Finish().
  • En cada Update elige el paso con una cadena de if / else if que empieza desde el final de la receta:
    1. ¿La bandeja ya tiene la bebida? → "Apretá E en la bandeja para entregar"
    2. ¿La tenés en la mano? → "Llevala a la bandeja"
    3. ¿Está lista en la máquina? → "Retirala"
    4. ¿La máquina está trabajando? → "¡Esperá!"
    5. Si no: "Agarrá el ingrediente"
  • Como se fija en el estado real del juego (la mano, las máquinas, las repisas, la bandeja), se acomoda sola si el jugador se equivoca o hace las cosas en otro orden.
  • La flecha es un prefab que se crea con Instantiate en Start. Se mueve arriba y abajo con un temporizador.

HUD, pausa, sonidos, menú, globos y animación

HUD

La barra de arriba muestra los pedidos "3 / 15" con una barra de progreso (Image en modo Filled, fillAmount), la plata de las propinas y 3 corazones (las vidas). Abajo hay un cartel de mensajes: ShowMessage(text, seconds = -1, wait = false) usa parámetros opcionales. Con wait = true, el mensaje espera a que termine el anterior. El cartel se oculta con un temporizador en Update.

Pausa (PauseMenu)

Esc alterna el panel. Pause() pone Time.timeScale = 0 y Resume() lo vuelve a 1. No deja pausar si la partida ya terminó. Las estaciones y el barista chequean Time.timeScale == 0f para no reaccionar en pausa.

Sonidos

Un AudioSource en el HUD y 9 AudioClip asignados en el Inspector. Cada función (PickUp(), Error(), MachineReady()…) hace PlayOneShot. Las estaciones lo buscan la primera vez que lo necesitan (GetSoundEffects()).

Menú principal

Paneles (Principal, Cómo jugar, Créditos) que se prenden y apagan con SetActive. Cómo jugar tiene 3 páginas en un array GameObject[]: Siguiente y Anterior "dan la vuelta" al llegar a la última o a la primera. Jugar carga la escena con SceneManager.LoadScene("Cafeteria").

Catálogo y globos

ItemCatalog es el único lugar que sabe qué sprite tiene cada objeto: un switch sobre ItemType que devuelve el Sprite. También crea los globos con Instantiate del prefab Globo. Los globos no son hijos del objeto: lo siguen en LateUpdate (que corre después de que todo se movió) para no quedarse atrás.

Animación del barista

El Player tiene un Animator con Player.controller, que tiene 4 estados: Walk_Down, Walk_Up, Walk_Left y Walk_Right. Cada clip tiene los 9 cuadros de esa dirección de la hoja walk.png. En PlayerMovement.UpdateAnimation():

if (movement.x > 0)      currentAnimation = "Walk_Right";
else if (movement.x < 0) currentAnimation = "Walk_Left";
else if (movement.y > 0) currentAnimation = "Walk_Up";
else if (movement.y < 0) currentAnimation = "Walk_Down";

if (isWalking) { animator.speed = 1f; animator.Play(currentAnimation); }
else               { animator.Play(currentAnimation, 0, 0f); animator.speed = 0f; }

Quieto, vuelve al primer cuadro (el barista parado) y frena la animación. Como currentAnimation guarda la última dirección, queda mirando hacia donde caminó. El movimiento en sí usa Rigidbody2D.MovePosition en FixedUpdate, para respetar los choques con las paredes y los muebles.

Un pedido de punta a punta: café con leche

Este recorrido sirve para el video: muestra cómo se pasan la información los scripts.

  1. GameManager elige el pedido (Random.Range sobre los arrays) y llama a customer.AssignOrder(CoffeeWithMilk, None) y a customer.Enter().
  2. CustomerMovement lo hace caminar de la puerta al puesto. Al llegar, Cliente.ShowOrder() activa la bandeja, muestra el globo con el pedido y arranca la paciencia.
  3. El barista va a Ingredientes y aprieta Z: IngredientStation llama a inventory.PickUpItem(CoffeeBeans), y el globo del barista muestra los granos.
  4. Se acerca a la moledora y aprieta E. PlayerInteraction encuentra la estación más cercana y llama a Interact; como es una CoffeeGrinder, corre su versión: suelta los granos y arranca el temporizador de 3 s.
  5. Cuando termina, otra E le da GroundCoffee. En la Cafetera, el switch entra en case GroundCoffee y, a los 4 s, hay Coffee.
  6. Lo apoya en una Repisa (no combina con nada, así que va a un espacio libre).
  7. X para leche, E en la cafetera (case Milk) y, a los 3 s, sale FoamedMilk.
  8. E en la repisa con la leche en la mano: Combine(Coffee, FoamedMilk) devuelve CoffeeWithMilk, que queda en ese espacio.
  9. Con las manos vacías, E en la repisa: agarra el café con leche.
  10. E en la bandeja: IsDrink es true y la apoya, con su dibujo encima.
  11. Otra E con las manos vacías: la bandeja pregunta customer.IsCorrectOrder(CoffeeWithMilk, None) y da true. Vacía la bandeja y llama a customer.ReceiveOrder().
  12. Cliente avisa a gameManager.OrderCompleted(this): suma el pedido, calcula la propina según la paciencia que quedaba, actualiza el HUD y suena "entregar". Si llegaste a 15, gana.
  13. El cliente se retira, espera 2 s y CustomerLeft hace entrar a otro con un pedido nuevo.

Preguntas probables en la defensa

¿Cómo sabe el juego qué objeto tiene el barista?

Con una variable currentItem de tipo ItemType (un enum) en PlayerInventory. Las máquinas la consultan con GetCurrentItem() y la comparan con ==.

¿Por qué un enum y no strings o números?

Con nombres fijos no hay errores de tipeo: si escribo mal, no compila. Y se lee mejor ItemType.Milk que un 2.

¿Qué es la herencia y para qué la usaste?

Todas las estaciones que se usan con E heredan de InteractiveStation. La base tiene virtual Interact y cada una hace override. Así PlayerInteraction trata a todas igual (un solo array, una sola llamada) y cada una reacciona distinto. protected Notify evita repetir el código de mostrar mensajes.

¿Cómo elige qué estación usar con la E?

Recorre el array de estaciones con un for, mide la distancia del barista al borde de cada una y se queda con la menor, siempre que sea menor que el alcance. Saltea las desactivadas con continue.

¿Por qué buscás las estaciones en Start y no en Update?

Porque buscar objetos en la escena es lento. Lo hago una vez y guardo el resultado en un array, igual que el GetComponent guardado en Start que vimos en clase.

¿Cómo hacés que una máquina tarde X segundos sin corrutinas?

Con un temporizador en Update: un bool preparing y un float timeRemaining al que le resto Time.deltaTime cada frame. Cuando llega a 0, el producto está listo.

¿Qué es Time.timeScale y dónde lo usás?

Multiplica el paso del tiempo. En 0 congela todo lo que usa deltaTime. Lo uso para la pausa y al ganar o perder. Al reiniciar o ir al menú lo vuelvo a 1.

¿Cómo combina la repisa las bebidas?

Antes de apoyar, recorre sus espacios y llama a Combine(lo que hay, lo que traigo). Si son café preparado y leche espumada (en cualquier orden), devuelve café con leche, y lo mismo con el chocolate. Si no combinan, devuelve None y lo apoya en un lugar libre.

¿Cómo se decide si el pedido es correcto?

La bandeja le pasa al cliente su bebida y su galletita, y el cliente compara las dos con lo que pidió usando &&. Las dos tienen que coincidir, incluso None si no pidió galletita.

¿Qué son los arrays paralelos?

Dos arrays del mismo largo donde la posición i de uno corresponde a la posición i del otro. En PlayerInteraction, stations[i], drawings[i] y colliders[i] son de la misma estación. En la repisa, slots[i] y bubbles[i].

¿Cómo funcionan los parámetros opcionales que usaste?

Tienen un valor por defecto en la declaración, por ejemplo Notify(string message, bool isError = true) o ShowMessage(text, seconds = -1f, wait = false). Si no los paso, se usa ese valor.

¿Cómo se calcula la propina?

Base 5 más hasta 10 extra según la paciencia que le quedaba al cliente (de 0 a 1): baseTip + (int)(maxExtraTip * percent).

¿Qué cosas usaste que no vimos en clase?

Collider2D.ClosestPoint (el punto del borde más cercano), FindObjectsByType/FindFirstObjectByType (la versión nueva de FindObjectOfType), Vector3.MoveTowards, Mathf.Max, animator.Play y AudioSource.PlayOneShot. Todos están explicados en los comentarios.
